This walkthrough uses your Ubuntu 22.04 t530 and Windows PC. No router mirror, additional physical NIC, external AP or Kali VM is required.

| E. Return results | Your editor | About ten minutes | One filled Markdown handoff |

These are planning allowances, not measured t530 benchmarks. Work in order. Stop at the first unexpected failure. You can return Stage A before attempting B or C.

**Established by successful tests:** software/feature behavior within tested cases, observations from PC-1, and operator-driven containment in a small routed Linux lab.

**Still unestablished:** whole-home visibility, phone/IoT Internet baselines, site-v3 RF/AE accuracy, automatic behavioral firewall decisions, commercial-vendor compatibility and production capacity. The home collector retains UNKNOWN ground truth and does not run the legacy models.

The live collector skips locally outgoing packet copies because it was designed for mirror input. Here we capture both directions with Dumpcap/tcpdump and replay the saved PCAP. Do not substitute live collection on an ordinary endpoint/router interface and assume equivalent directional coverage.

Keep actual addresses, manifests, logs and PCAPs private. Raw captures can contain payloads even though the derived CSV contains reduced features. Return a redacted results file initially.

## Stage D progress and decoder fix · 2026-11-08

Stage D started with two gaming workloads, replayed on the t530 from the commit 8a24d8b checkout: a 49-minute session and a three-hour session captured as three 60-minute parts. Every audit reported REVIEW with no integrity issues, UNKNOWN labels only and PC-1 as the only device. Each dumpcap run in the three-hour session stopped at its 3,600-second limit before the next was started, which left two unrecorded gaps of 132 s and 229 s. Use a ring buffer (`-b duration:3600`) for long sessions.

Reconciling parser counts with tshark exposed a decoder gap at this capture point. The large-send super-segments noted above carry an IPv4 total length of 0. The decoder treated their payload as empty, so their ClientHellos and outgoing payload bytes were missing. ClientHellos sent after a TLS 1.3 compatibility ChangeCipherSpec record were also skipped. Together these hid 18–27% of TCP ClientHellos. The counts reconcile exactly: in the 49-minute session, 340 TCP ClientHellos − 87 offloaded − 5 retries = 248 counted. The [changelog](/reference/change-log) describes the fix. With the fixed decoder, a local replay of the same capture counted 340 ClientHellos, 752 zero-length frames and an outgoing payload sum equal to tshark's.

G14 payload and G16 values from these replays, and from the 2026-11-07 Stage B replay, predate the fix. The t530 then re-ran Stage A from a fresh checkout of the fixed commit eb1c58a, with 136 tests OK, golden PASS (142 checks) and runtime PASS (4,000 rows). It re-replayed all five stored captures into a new run directory.

| Capture | Rows | G16 before → after | tshark TCP ClientHellos | `ipv4_zero_length_frames` |
| --- | --- | --- | --- | --- |
| Stage B browsing, 10 min | 121 | 12 → 17 | 17 | 36 |
| Gaming, 49 min | 586 | 248 → 340 | 340 | 752 |
| Gaming, hour 1 | 721 | 174 → 214 | 214 | 2,810 |

Each audit reported REVIEW with no integrity issues. A stdlib PCAP reader produced the same zero-length counts. The tshark column decodes TCP port 5222 as TLS: by default tshark treats that port as XMPP and misses one ClientHello in hour 1. Rows, direction totals and DNS, HTTP, eviction, reorder and parse-error counters were identical to the pre-fix replays, and the new directories carry the new schema hash. Use these directories, not the pre-fix ones, for G14 payload and G16 values. Endpoint replays report `ipv4_zero_length_frames`, which is expected at this capture point.

## B1. Prepare Windows endpoint capture

**Windows PC: PowerShell, elevated if your capture driver requires it.**

Install Wireshark from its [official download page](https://www.wireshark.org/download.html), including the offered Npcap component. Existing installations are usable. Make installer/driver choices locally.

~~~powershell
$Dumpcap = Join-Path $env:ProgramFiles 'Wireshark\dumpcap.exe'
Test-Path $Dumpcap
& $Dumpcap -D
Get-NetIPConfiguration
$CaptureInterface = [int](Read-Host 'Dumpcap interface number')
& $Dumpcap -i $CaptureInterface -L
~~~

Expected: Test-Path True; select the physical Ethernet/Wi-Fi interface carrying your PC's traffic, not loopback, VPN or a VM adapter. Dumpcap's number may differ from Windows' interface index.

The supported link type is Ethernet, typically EN10MB. If only raw Wi-Fi/radiotap or another link type is available, stop and report it; the present decoder expects Ethernet.

Record actual addresses on that interface:

~~~powershell
Get-NetIPAddress | Select-Object InterfaceAlias, AddressFamily, IPAddress, PrefixLength
$PcV4 = (Read-Host 'Current PC IPv4 address on that interface').Trim()
$PcV6 = @((Read-Host 'Current PC IPv6 addresses, comma-separated; Enter if none').Split(',') | ForEach-Object { $_.Trim() } | Where-Object { $_ })
$Activity = Read-Host 'Activity category, e.g. qualification-browsing'
$SessionId = 'pc-' + (Get-Date).ToUniversalTime().ToString('yyyyMMddTHHmmssfffZ')
$PcRoot = Join-Path $env:USERPROFILE 'AdaptiveIPS-Pilot'
$PcSession = Join-Path $PcRoot $SessionId
New-Item -ItemType Directory -Path $PcSession -ErrorAction Stop | Out-Null
$CaptureFilter = (@("host $PcV4") + @($PcV6 | ForEach-Object { "host $_" })) -join ' or '
$Manifest = [ordered]@{
    version = 'endpoint-pilot-v1'
    session_id = $SessionId
    capture_point = 'windows_endpoint'
    ipv4 = $PcV4
    ipv6 = $PcV6
    activity = $Activity
    ground_truth = 'UNKNOWN'
    offload_review = 'PENDING'
    requested_start_utc = (Get-Date).ToUniversalTime().ToString('o')
}
$Manifest | ConvertTo-Json -Depth 4 | Set-Content -Encoding utf8 (Join-Path $PcSession 'session.json')
& $Dumpcap -v 2>&1 | Set-Content (Join-Path $PcSession 'capture-version.txt')
Write-Output "Private session directory: $PcSession"
Write-Output "Session ID: $SessionId"
~~~

If addresses change, end the session and start another with updated addresses. Unlisted IPv6/privacy addresses are outside this filter. If you supplied no IPv6 addresses, mark IPv6 UNOBSERVED. These manifests contain real addresses: keep them outside Git and omit them from the initial handoff.

## B4. Replay using the PC's exact address scope

**Ubuntu terminal A.** The helper reads the private manifest and calls existing CLIs. IPv4 /32 and listed IPv6 /128 scopes keep derived device rows tied to this PC.

~~~bash

import hashlib
import ipaddress
import json
from pathlib import Path
import subprocess
import sys

directory, code, run = map(Path, sys.argv[1:])
manifest = json.loads((directory / "session.json").read_text(encoding="utf-8-sig"))
if manifest["version"] != "endpoint-pilot-v1" or manifest["capture_point"] != "windows_endpoint":
    raise SystemExit("Unexpected manifest; stop and review")
if manifest["session_id"] != directory.name or manifest["ground_truth"] != "UNKNOWN":
    raise SystemExit("Manifest identity/truth mismatch")
v4 = ipaddress.IPv4Address(manifest["ipv4"])
v6 = [ipaddress.IPv6Address(value) for value in manifest["ipv6"]]
output = run / ("replay-" + directory.name)
report = run / ("report-" + directory.name + ".json")
if output.exists() or report.exists():
    raise SystemExit("Existing replay/report refused; preserve it and choose a fresh run")
pcap = directory / "endpoint.pcap"
digest = hashlib.sha256()
with pcap.open("rb") as source:
    for chunk in iter(lambda: source.read(1024 * 1024), b""):
        digest.update(chunk)
print("PCAP SHA256:", digest.hexdigest(), flush=True)
command = [sys.executable, str(code / "Controller/home_sensor.py"),
           "--pcap", str(pcap), "--data-dir", str(output), "--port", "18081",
           "--metadata", "--http", "--max-data-gib", "1", "--min-free-gib", "1",
           "--lan", str(v4) + "/32"]
for address in v6:
    command += ["--lan", str(address) + "/128"]
subprocess.run(command, check=True)
print("Closed replay:", output, flush=True)
completed = subprocess.run([sys.executable, str(code / "scripts/audit_home_data.py"),
                            str(output), "--output", str(report)])
print("Private audit:", report, "exit:", completed.returncode, flush=True)
raise SystemExit(completed.returncode)
PY
~~~

- Its dashboard exists during replay and closes afterwards. A refused connection afterwards is expected.
- Labels stay UNKNOWN. No site-v3 RF/AE decision or firewall action occurs.
- Audit exit 2 / REVIEW is expected for replay, unavailable live kernel-loss evidence, partial final windows and observation-only holds. It is not baseline approval.
