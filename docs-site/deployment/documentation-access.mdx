## Windows documentation preview on port 3333

The straightforward Windows background command is now:

```powershell
cd "D:\Graduation Project\data\Claude Code Magic\GP"
.\scripts\start_docs.cmd
```

It runs Node directly rather than a PowerShell script file, so it does not require an execution-policy change or finding mint.cmd through PATH. Node is resolved from PATH or the standard Program Files installation. The helper checks local/common-global package locations, reads mint's package.json bin declaration, requires the tested 4.2.1195 package and an existing entry file, and waits for HTTP 200 containing the site name. Its default is a hidden detached background process on port 3333 with logs under .local/docs-preview. Close the terminal after ready/already_ready. Restarting Windows still requires another launch; no login task was installed.

If Node reports MODULE_NOT_FOUND, it did not start the site. A package.json or shim alone does not establish a complete installation. In the standard Node installation, repair the tested package with:

```powershell
& "$env:ProgramFiles\nodejs\npm.cmd" install --global mint@4.2.1195
.\scripts\start_docs.cmd
```

For a custom npm prefix, install locally without a repository-wide dependency upgrade: run the following from docs-site, then run start_docs.cmd from the repository root. Generated node_modules/package-lock material is local; inspect Git before committing anything.

```powershell
& "$env:ProgramFiles\nodejs\npm.cmd" install --no-save --package-lock=false mint@4.2.1195
```

Use --port 3334 or --timeout 180 explicitly if needed; occupied unrelated ports are refused rather than silently moved. --foreground is available for debugging. If a node-start-PORT.lock remains after an interrupted launcher, inspect its recorded PID and running command before removing only that stale lock; the helper does not kill processes automatically. A timeout can leave a preparing process, so inspect logs/port before retrying. CLI flags and Node process behavior follow [Mintlify's own CLI](https://www.npmjs.com/package/mint) and [Node child-process documentation](https://nodejs.org/api/child_process.html); the repository pins its tested CLI and CI's Node 22 environment rather than assuming newest-version compatibility.

From the repository root in PowerShell, run:

```powershell
.\scripts\start_docs.ps1
```

Open **http://localhost:3333/**. This starts the actual Mintlify site independently of collection and the controller. The background process survives closing the launching terminal. It serves the checked-out docs-site directory and reloads edited pages. Run the helper again after restarting Windows; an already healthy preview is reused. Install npm's mint@4.2.1195 globally if the helper reports it missing.

The helper fixes the working directory and port, reads the current site name from docs.json and waits for a successful response containing that name. Renaming the documentation therefore does not require a second hardcoded title in the launcher. It reports startup failures and logs output under .local/docs-preview, which is ignored by Git. A different service occupying the requested port is an error rather than a reason to move silently to another port. Use -Port to choose another port explicitly. For visible console output, use -Foreground. First preparation can require network access and take longer than subsequent starts.

ERR_CONNECTION_REFUSED at localhost:3333 means that local address has no accepting listener. Start the preview before opening the browser. If startup fails, inspect mint-3333.stdout.log and mint-3333.stderr.log in the log directory. A local preview is available on the workstation where it runs; accessing the t530's sensor documentation uses the separate tunnel below.

## Sensor documentation on port 8081

The home sensor and passive sensor serve the checked-out documentation at **/docs** on their dashboard origin. Through the same SSH tunnel, open http://127.0.0.1:8081/docs. This lightweight local reader loads MDX/Markdown pages from docs-site on each request. After pulling a code/documentation update, refresh the page. The page matches that checkout's version. Native Mintlify search, interactive API components and Mermaid rendering use the Mintlify site; the local reader presents Markdown, tables, code, simple cards and step headings.

Every implementation change belongs with updated pages and a dated entry in the [implementation changelog](/reference/change-log). New routes require the corresponding OpenAPI update. The versioned commit hook and push/PR documentation guard require both the changelog and an affected page according to the source map. Mintlify checks also run in CI. Reviewers check accuracy and coverage; repository branch rules must require the checks to make failed checks block merging.

## Keep the hosted Mintlify website current

Connect the repository D3ath7274/GP in your Mintlify account. Select the branch containing your reviewed changes. Enable the setting that docs.json is in a subdirectory and set the directory to **/docs-site**. After the GitHub connection is authorized, Mintlify builds the connected branch when updates arrive. Your public site URL is supplied by the Mintlify account. See [Mintlify's repository and folder setup](https://www.mintlify.com/library/publish-open-source-local-docs-on-mintlify).

The locally served pages are available while the sensor runs, including across reboots when its systemd service is enabled. The hosted site can stay available independently of the sensor. Confirm the connected branch and update the t530 checkout deliberately so that the hosted and installed versions agree.
