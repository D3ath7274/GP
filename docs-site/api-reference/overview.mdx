title: "API boundaries and runtime selection"
---

| Process | Contract | Authority |
| --- | --- | --- |
| Site-v3 home collector, loopback 8081 | collection-openapi.json; [collection reference](/api-reference/collection) | Observation/schema/health/shadow reads, static dashboard and local docs; no firewall or model writes |
| Policy workbench, loopback 8082 | policy-openapi.json; [policy reference](/api-reference/policy-workbench) | Read-only operator-model snapshots, search, audit, impact and hypothetical previews |
| Retained Ryu lab controller, configured 8081 | openapi.json, legacy reference only | Block/unblock affect its lab datapaths; software success does not prove containment |

These similarly named routes are separate processes/contracts. The two 8081 services cannot share the same bound address/port. The passive reference sensor only implements its documented read subset and does not inherit Ryu writes. The shared http_dashboard handler delegates reads to the supplied collector and rejects unsupported methods.

There is no native vendor policy apply endpoint. The nftables reference CLI is operator-run, separate from both read-only services. Bind management locally and use the documented private tunnel; an internet-facing product management plane with authenticated roles is future work.

Use [the workbench](/deployment/policy-workbench), [site collection](/deployment/home-collection) and [legacy reference](/deployment/passive-sensor) guides for the chosen process. Do not infer authority from the dashboard's appearance.
