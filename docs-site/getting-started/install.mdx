---
title: "Prepare the active development environment"
---

Site collection and offline policy audit do not need Ryu or the shipped RF/AE models. Use Python 3.10 on Ubuntu 22.04 for the target pilot, with a separate virtual environment. Keep the system Python symlink intact. The workstation may run the offline checks without raw-socket privileges.

```bash
python3 -m venv .venv-home
. .venv-home/bin/activate
python -m pip install -r Controller/requirements-home.txt
python -m unittest discover -s tests
python scripts/check_feature_catalog.py
```

For Windows use the virtual environment's Scripts/python.exe explicitly if shell activation is blocked. The dependencies support collection/qualification only. Model artifacts have a different dependency and input contract; see [the reference lane](/deployment/passive-sensor).

Proceed to [offline quickstart](/getting-started/quickstart), [the no-mirror pilot](/deployment/no-mirror-pilot) or [qualified collection](/deployment/home-collection). Do not start a multi-day capture until its actual traffic visibility and measurement checks pass.
