Use [the study roadmap](/developers/study-roadmap) to build competence and [the AI continuation context](/developers/ai-handoff) to orient a future session. PROJECT_AI_HANDBOOK.md combines authored architecture with a purpose for every tracked file and an AST symbol/import index. scripts/build_ai_handoff.py reads tracked paths and source/metadata without importing runtime modules or unpickling artifacts. Text fingerprints normalize CRLF/LF; binary model hashes remain raw. This avoids false Windows/Linux drift. Missing/obsolete purpose entries and stale generated context/index/fingerprints fail the hook/CI. Semantic correctness still requires review.

After source edits or new/deleted tracked files, update docs-site/reference/file-purposes.json and affected authored context; stage new paths, run python scripts/build_ai_handoff.py --write, review/stage its two outputs, then run its --staged check. Local-only datasets/agent settings are described as excluded, not ingested. tests/test_ai_handoff.py checks conditional/nested AST extraction, exact purpose coverage, private-input exclusion by access contract, normalized text/raw artifact hashing and Git-index readers.

scripts/start_docs.cmd/start_docs.cjs add a Windows route without PowerShell file-policy changes. The helper validates the package's declared executable and tested version before spawning, checks port/brand readiness, detaches hidden log-backed children and reuses an existing healthy site. Missing package entry, wrong package version, busy port, startup exit/timeout and stale lock are explicit errors. tests/test_docs_launcher.cjs uses Node's built-in test runner, including an owned detached fixture process; CI runs it with Node 22. The user's Node 26 installation passed current startup checks, but that is not a blanket upstream compatibility claim. Use the [access guide](/deployment/documentation-access) for repair/restart commands.

CommonJS .cjs files are explicitly classified as implementation alongside .cmd wrappers by the documentation guard; future standalone launcher edits therefore require their mapped MDX page and dated changelog. The existing classification regression covers both extensions.

Feature work must update [the source-mapped rationale](/architecture/feature-rationale) and docs-site/reference/feature-groups.json. Run python scripts/check_feature_catalog.py and its --staged variant; the local hook now runs it after documentation synchronization, and CI checks the committed snapshot. It parses column definitions without loading capture/models, rejects missing/duplicate/invented assignments and planned implementation claims, and requires rationale for all G1–G24/supporting categories. It does not verify mathematical definitions or a model's actual input selection. Formula/missingness changes still require independent tests, schema decisions and qualification.

The offline-qualification CI job now targets Ubuntu 22.04/Python 3.10, installs only Controller/requirements-home.txt and runs the full offline unit/CLI/HTTP suite plus catalog check. It needs no live sensor, raw-socket permission, Ryu or firewall credential. Its remote status must be checked after push; adding a workflow is not evidence it has run. Replays do not replace actual t530 capture/capacity qualification. Require the relevant checks in repository branch rules if enforcing merges; those owner settings are separate. The runner preserves unittest's failing exit status and emits escaped failure tracebacks as GitHub annotations, so failures can be diagnosed from check results as well as job logs. Tests use sanitized fixtures and must not ingest private household data or credentials.

That target job exposed an empty-query compatibility error in the policy viewer. The HTTP regression now covers no-query and bare-question-mark routes as well as malformed/unknown/repeated fields. Keep this test on Python 3.10: newer Python query parsers do not reproduce the same empty-input failure. An empty query becomes no parameters; supplied queries still require strict parsing. Use `python -m unittest discover -s tests -p test_policy_workbench.py` for the focused suite and review the Ubuntu job before claiming target compatibility.

The [policy-change code tour](/developers/policy-change-code-tour) covers counterfactual partitioning, possible-match uncertainty, exact-base hypothetical requests, private new-only receipts and replay verification. Tests compare access changes/witnesses with an independent exhaustive oracle and require unchanged SQLite bytes across CLI/HTTP previews. No new dependency, runtime model, home feature column or native firewall write path is introduced by this milestone. Stop/restart the workbench after a code update to avoid mixing a loaded engine with a new checkout.

Update the relevant page and [implementation changelog](/reference/change-log) in the same contribution. REST contract changes also require an OpenAPI update. The repository hook and push/PR check require both a dated changelog entry and an affected MDX page from documentation-map.json. First-match mapping rules associate source patterns with allowed pages; unknown code requires this developer page until its own rule is added. Update both the map and human coverage matrix when introducing an area. Dependency, internal tooling and CI changes also require a record.

Run python scripts/check_docs_sync.py --staged after staging the implementation, page and changelog. Unstaged edits, unrelated pages and deleted mapped pages cannot satisfy the guard. The --base option checks a PR merge base; --from checks an exact previous commit/tree for a push. GitHub also runs the pinned Mintlify build, link and accessibility checks. Required branch status checks must be configured in GitHub to block merging failures. Automated checks verify documentation inclusion and structural validity; reviewers assess the description's accuracy.

For a local preview independent of the controller, run scripts/start_docs.ps1 from PowerShell at the repository root, then open http://localhost:3333/. The helper verifies readiness, keeps logs in .local/docs-preview and starts a hidden process that survives its launching terminal. See [documentation access](/deployment/documentation-access) for restart and troubleshooting instructions. Tests in tests/test_docs_sync.py exercise the guard in isolated Git repositories, including staged-versus-working-tree behavior and both CI diff modes.
