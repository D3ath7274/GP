## Why this consolidation exists

The active product goal is behavioral firewall auto-audit and eventually verified adaptive response across qualified adapters (S01–S70). Multiple old launchers, topology-specific instructions and duplicate plans made it unclear which path to test. Cleanup does not implement new enterprise services, change feature formulas or qualify automatic blocking.

Use home_sensor.py for site measurements/shadow profiles, policy_inventory.py for offline policy audit/change review, the no-mirror pilot for current experiments, and nft_quarantine.py for a separate operator-run namespace test. Native vendor collection/writes, reachability/NAT, calibrated site models and a durable closed control loop remain planned under P0–P13.

## Retained intentionally

- Every legacy/site feature implementation and all G1–G24 rationale/catalog entries. G18–G24 remain planned. [Feature lineage](/architecture/feature-lineage) also preserves the superseded proposal's unimplemented measurement names/formulas.
- Trusted shipped RF/AE artifacts, H5 weights and rebuilding scripts. Existing model import paths remain compatible; this is not a model release.
- Controller_main_Claude.py, ipsctl.py, ips_config.json and traffic_mirror.py as a lab reference lane: the controller contains DAI and the original OpenFlow actuator. See [legacy behavioral reference](/deployment/passive-sensor). These are not required by the site collector or policy workbench.
- SnortManager and Snort 3 Lua/rules for signature comparison; the integrated lab path remains. Alternate HTTP relays, absent-app launchers and old installers are removed. No Snort 2 package installation replaces them.
- Collection leases/checkpoints, offline qualification fixtures/tests, policy analyzers, read-only APIs, the operator nftables adapter and all current service requirements/release gates.
- Current study roadmap, source-checked AI handbook, documentation launchers/guards and no-mirror pilot/results template.
