Actual H188A visibility remains unresolved; the offline lane includes executable tests and next phase requirements. Verification is recorded in DOCUMENTATION_VALIDATION.md.

## 2026-11-04 · Timed one-NIC wired/Wi-Fi home pilot

Rewrote [the home pilot](/deployment/home-pilot-step-by-step) for the reported single-Ethernet Ubuntu t530. The recommended passive topology places a bridged external AP and wired PC behind a managed mirror switch; monitored phones migrate to that AP. Added required source/direction port settings, duplicate/oversubscription checks, same-AP and WAN-side blind paths, explicit local-console/shared-port/separate-management choices and NTP/reboot gates. New step-by-step Ubuntu/Windows commands cover preparation, persistent terminals, scoped temporary HTTP probes/cleanup, per-phone/Internet/IPv6 tests, timed header/metadata captures, service setup, daily quality review and rollback. Wait schedules progress from 60-second probes through 10/20-minute checks, one hour, 24 hours and an initial fourteen days. No runtime code, live device setting or REST contract changed. Source/script syntax, links, site rendering and documentation checks are recorded in DOCUMENTATION_VALIDATION.md; actual ZTE/switch/AP behavior and t530 execution remain unverified.

## 2026-11-04 · Pre-test evidence, recovery and deterministic policy audit

Added a [qualification toolkit](/deployment/pretest-qualification): noncreating prerequisite/visibility-attestation preflight; hand-derived golden PCAP expectations for all feature columns; bounded accelerated restart/resource exercise; shared writer/reviewer/report lease; stricter profile restoration; source/environment run fingerprints; paired closed-file evidence, rates, run totals, overlap, daily/device/gap/parser reports. CSV and collection REST contracts remain unchanged. The audit now refuses active writers, fails torn/mismatched evidence and returns REVIEW for partial/held/unclosed/replay/unversioned intervals; operators must stop collection and investigate rather than silently repair or approve data. New [campaign scoring](/deployment/security-campaigns) keeps independent truth, qualified arrival/coverage, abstentions, misses, false alerts, read-back and actual traffic containment separate. It does not enable scoring or mitigation in home collection.

Added the [first P8 audit subset](/deployment/policy-audit) for partial S20–S23/S26–S30: bounded header-region algebra for duplicate/union-shadow/redundant/partial-overlap witnesses plus model-scoped metadata/object review. A CLI audit command, read-only viewer button and GET /policy/audit expose the same algorithm; the API contract includes caps and uncertainty. ANY is restricted to the supported protocol domain; native semantics, schedules/profiles/NAT/routes/usage and deletion safety are unqualified. No cleanup or firewall write occurs. The [code walkthrough](/developers/qualification-code-tour) explains each new path and test oracle.

Verification includes independent golden comparisons, accelerated synthetic restart rows, full unit/CLI/HTTP/failure checks, documentation guard and Mintlify checks recorded in DOCUMENTATION_VALIDATION.md. Actual Linux socket quality, H188A mirror capability, t530 multi-day resources, independent attack campaigns and native firewall qualification remain pending hardware/data evidence.
